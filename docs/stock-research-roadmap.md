# 股票研究方向路线图

这个文档描述 Harness 的股票研究方向。当前已经有一条可运行的真实数据研究链路，但它仍是只读、延迟数据和
探索性拟合，不代表实时行情、完整市场覆盖或可交易信号。

## 当前闭环：杠杆序列与价格路径对照

页面入口是 `GET /api/finance/research`，前端对每个市场分别展示价格 K 线、杠杆输入、拟合价格路径、
验证区间和来源证据。当前接入：

```text
A股   上交所融资余额 rzye + WeStock 上证综指日K
港股   WeStock 腾讯控股 ShortRatio + 日K
美股   WeStock Apple ShortRatio + 日K
韩股   未接入
```

A 股只使用上交所汇总口径，不能把它描述成全市场融资余额；港股和美股的 `ShortRatio` 是供应商字段，
不是我们推导出来的“杠杆率”。WeStock 日 K 线可能延迟，报告日缺口会向前填充并在页面中标记。

真实源失败时，服务只返回仍能取得的市场；如果全部真实源失败，明确返回错误，不使用历史 `fixture://a-share-leverage`
或其它 Fixture 作为线上降级。

## 方程和验证

拟合目标是下一交易日对数收益：

```text
r(t+1) = β0 + β1·z(Lt) + β2·z(ΔLt) + β3·z(M5t) + β4·z(M20t) + ...
```

其中 `L` 是当前市场自己的杠杆字段，`ΔL` 是日变化，`M5/M20` 是价格动量；只在同一序列内做 z-score。
候选模型按时间顺序切成 70% 训练集和 30% 验证集，用验证 RMSE 选择，而不是随机打乱。预测收益复合成
归一化价格用于绘图，并同时输出 RMSE、R² 和相关性。

这套方法的第一价值是验证“杠杆是否包含解释力”。如果验证相关性接近 0，页面必须显示这个结果；拟合曲线
不能被解释成预测，也不能据此自动下单。

核心指标包括：

- 融资余额 / 流通市值。
- 融资买入额 / 市场成交额。
- 5/20/60 日融资余额变化率。
- 融资余额距 250 日高点的回撤。
- 20 日净偿还压力。
- 20 日实现波动率和上涨股票比例。

所有指标先转换成历史分位数，再计算 Heat、Clear 和 Confirmation。评分是可追踪规则，不是固定的买卖阈值。

## 计划增加的领域对象

- `StockRef`：市场、代码、名称和数据时间。
- `SourceEvidence`：来源 URL、发布时间、摘录、抓取时间和来源类型。
- `MetricSnapshot`：收入、利润、现金流、估值等指标及其期间。
- `RiskCheck`：风险项、证据、结论和未确认原因。
- `ResearchReport`：事实、推断、限制、风险和引用的分离结果。
- `MarketLeverageObservation`：交易日、融资余额、融资交易、流通市值、成交额、指数和市场宽度。
- `LeverageMetricSnapshot`：杠杆比例、增长率、出清幅度、净偿还压力和波动率。
- `LeverageScoreSnapshot`：Heat、Clear、Confirmation、市场状态和计算证据。

这些对象应该作为 `Artifact` 的结构化内容存在，不应该直接埋在 Prompt 或聊天历史里。

## 事实、推断和风险必须分开

报告至少分成三层：

```text
事实：来源明确支持的数字、公告或经营信息
推断：基于事实做出的比较或解释
风险：数据缺失、口径不一致、时间过期和结论失效条件
```

Verifier 不只检查“报告文件生成了”，还要检查：每个关键事实有来源、指标期间没有混淆、推断没有冒充
事实、风险章节没有被省略。

## 后续接入顺序

1. 增加数据快照持久化：原始响应、抓取时间、交易日期、命令和解析版本一起保存。
2. 接入可靠的韩股杠杆/卖空历史源，并把来源许可、频率和覆盖范围写进 SourceEvidence。
3. 增加真实的 A 股全市场两融序列，区分上交所、深交所和全市场口径，避免把单一交易所当成全市场。
4. 增加固定股票池、个股基本面和风险事件 Artifact。
5. 做滚动窗口、基准模型和跨市场对照，验证方程是否稳定，而不是只看单次样本的拟合。
6. 生成两股票对比报告，并验证每个关键事实的来源和期间。
7. 再让 Spring AI 负责某个 Task 的摘要或比较草稿；最后才评估并行采集、SSE 展示和更复杂的数据存储。

模型可以提出分析草稿，但不能直接改变股票、指标、来源或任务状态；最终报告必须经过 Java Harness
的验证器确认。
